# Trackpad layer behavior + zoom — design

**Date:** 2026-06-15
**Keyboard:** ZSA Voyager (`JRZ6Q`), Oryx + custom-QMK hybrid, Navigator trackpad.
**Host:** macOS.

## Problem

Four behaviors to change around the Navigator trackpad and layers:

1. **Click layer doesn't yield.** Touching the trackpad auto-activates the mouse
   layer (`AUTOMOUSE_LAYER = 5`, via the `zsa/automouse` module), which maps
   `S`/`D`/`F` to middle/right/left click. When another layer key is pressed
   (e.g. `MO(1)` for arrows), layer 5 stays on top and its click keys override the
   intended keys underneath.
2. **(Same root cause as 1.)** Pressing a layer button while the mouse layer is
   active should switch layers, not keep the mouse layer.
3. **Conditional layer 3 doesn't release cleanly.** Layer 3 is faked with stacked
   momentary keys — layer 1's right thumb is `LT(3, KC_0)` and layer 2's left thumb
   is `MO(3)`. A momentary key's function is locked in at press time, so releasing
   one thumb can leave the other still asserting layer 3 until both lift ("extra
   press").
4. **No trackpad zoom.** Pinch is emitted as Windows-PTP digitizer data that macOS
   does not interpret, and the pad is too small for pinch anyway. Two-finger scroll
   *does* work. The user zooms via modifier+scroll, but on the mouse layer the
   home-row mods for Ctrl (`D`) and Shift (`F`) are clobbered by the click buttons.

## Constraints

- The ZSA `navigator_trackpad`/`automouse` modules are upstream submodules pulled at
  build time — not forked here. Gesture synthesis inside the trackpad pipeline is out
  of scope. Fixes live in `JRZ6Q/keymap.c`.
- `keymap.c` is regenerated by Oryx and 3-way `git merge`d into `main`. **Added
  functions** Oryx never emits (e.g. `layer_state_set_user`) are merge-safe.
  **Edits to Oryx-generated lines** (keymap arrays) carry low merge risk — they only
  conflict if the same key is also edited in Oryx later.

## Design

All changes in `JRZ6Q/keymap.c`.

### New `layer_state_set_user()` (additive)

```c
layer_state_t layer_state_set_user(layer_state_t state) {
    // Task 3: layer 3 is on only while layers 1 AND 2 are both held.
    state = update_tri_layer_state(state, 1, 2, 3);

    // Tasks 1 & 2: the auto-mouse layer yields to any explicitly-held layer.
    if ((state & (1UL << AUTOMOUSE_LAYER)) && (state & ~(1UL << AUTOMOUSE_LAYER))) {
        state &= ~(1UL << AUTOMOUSE_LAYER);
    }
    return state;
}
```

- `update_tri_layer_state(state, 1, 2, 3)` makes layer 3 a *derived* state: on iff
  layers 1 and 2 are both active. Releasing either recomputes instantly → seamless.
- The mouse-layer strip: if layer 5 is set alongside any other layer bit, clear 5 so
  an explicitly-held layer always wins. Cursor motion is unaffected (separate
  digitizer path). `AUTOMOUSE_LAYER` comes from `config.h`.

### Keymap-array edits

| Layer | Position | From → To | Reason |
|---|---|---|---|
| 1 | right thumb | `LT(3, KC_0)` → `LT(2, KC_0)` | tri-layer needs layer-2 hold; tap stays `0` |
| 2 | left thumb | `MO(3)` → `MO(1)` | tri-layer needs layer-1 hold |
| 5 | left thumb (the Tab/Space dual-func one, **not** `MO(1)`) | `KC_TRANSPARENT` → `KC_LEFT_CTRL` | task 4: hold + scroll = ⌃ zoom |
| 5 | `G` (left index) | `KC_TRANSPARENT` → `KC_LEFT_SHIFT` | task 4: hold + scroll = horizontal scroll |

The layer-5 `MO(1)` thumb stays transparent so it still falls through to `MO(1)` and
switches to layer 1 (with the new yield behavior) while mousing.

## Behavior after change

- Trackpad → layer 5 (clicks). Any layer key → layer 5 drops, real layer takes over.
- Both thumbs → layer 3; release either → the remaining single layer, no stuck press.
- While mousing: inner-left thumb (⌃) + scroll = zoom; `G` (⇧) + scroll = horizontal;
  ⌘ still available on `A` via fall-through.

## Notes / risks

- On macOS, ⌃+scroll zooms page content in browsers/most apps; if *Accessibility →
  Zoom → "Use scroll gesture with modifier keys"* is on, ⌃ may zoom the whole screen
  instead — a System Settings toggle.
- Cannot compile locally (QMK firmware + modules are pulled only in the GitHub Action
  Docker build). Verification is by static review + the Action build.

## Out of scope

- Firmware-level pinch/gesture synthesis (would require forking the ZSA module).
- Changing the trackpad input mode or scroll behavior (scroll already works).
